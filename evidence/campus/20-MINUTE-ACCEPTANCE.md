# 四个 Base：20 分钟完整操作卡

## 使用范围与准备

本卡供一个验收操作者配合预先创建的负责人、核验者和普通成员账号，在**隔离验收学校**完成一次 20 分钟走查。下面的分钟分配是操作计划，不是已经发生的真人测试记录。已有自动化用例各自记录真实耗时；运行不足 20 分钟不能填写为“真人已验收 20 分钟”。

开始前完成服务安装、迁移、账号邀请、测试模型配置及独立备份恢复。这些耗时不塞进 20 分钟。使用两个原创示例学校，禁止向原始学校库、真实合作渠道或用户私有图纸项目写入测试数据。当前恢复克隆的地址及账号通过私有交接提供；密码、令牌和配置文件不写进本卡。

准备以下**明确标记虚构**的资料：

- 一个成员账号、一个负责人账号、一个与投稿人不同的活动核验者；浏览器使用隔离会话。
- 一个已审核活动及一个志愿任务，时间窗口覆盖本次验收，容量和候补条件明确；一份 512 KiB 以内的示例证据附件。
- 一个演示贡献规则版本、一个有限库存演示奖励，以及一个获准合作服务和演示权益；未连接真实商家时保留“未连接／示例适配器”标识。
- 一个待审帖子或地图记忆，避免为了凑时间绕过 NodeBB 既有发帖频率限制。

## 0–4 分钟：进入学校与可运行空间

1. 成员登录，确认可访问学校列表；尝试另一个未授权学校地址，应明确拒绝。
2. 打开学校空间，实际从入口走入一间公开房间，通过楼梯进入另一层房间，再返回入口。查看当前位置变化；不能只切换楼层视图就称为走通。
3. 查看接待姓名、Agent ID、维护职责和真实 A2A Card。问一个已发布资料问题，检查引用来源；普通交流按配置标明性质。
4. 打开一处展项和当前美术场景，确认模型、房间标识、信息及互动入口可读。390 px 窄屏检查只需一次。

**通过标准：** 当前身份与学校一致；未授权学校不泄露资料；真实导航到达正确房间/楼层并返回；渲染模型与导航共享几何 hash；引用来自当前发布资料。自动证据：`qa/campus/spatial/browser.json`、`qa/agents/live.json`、`qa/agents/browser.json`、`qa/campus/knowledge-postgres.json`。空间截图只用于观察视觉，不代替导航证据。

## 4–8 分钟：人物、背包与人与人的权限

1. 在人物页面选择发型、上装、配饰或颜色，预览动作并保存。用另一独立会话重新登录，核对相同配方与模型 hash。
2. 打开背包，装备已有校园地图或记忆卡；实际到达地点后使用一次，检查私有收藏/明信片及库存回执。场景结构不应变化。
3. 查看个人作品、组织与徽章；把一个自有字段保持私有，另一成员不能看到它。
4. 发起联系人请求，由对方接受后发一条私信；检查拒收或屏蔽状态。负责人不能凭管理身份任意读取双方私聊。

**通过标准：** 保存与重登一致；未知部件/CAS 冲突有清楚提示；道具需真实持有、装备和地点；重试不多扣；私有数据不进入公开接待。自动证据：`qa/avatar-extension/`、`qa/personal/`、`qa/campus/contacts-live.json`、`qa/campus/contacts-browser.json`，以及对应 M2 恢复记录。

## 8–13 分钟：论坛、地图记忆与贡献

1. 打开准备好的帖子/地图记忆草稿，核对学校、组织、分类和地图锚点，提交审核。
2. 切换负责人会话，写审核理由并发布。成员在论坛、搜索及对应地图地点看到同一来源、修订号和内容。
3. 查看贡献流水和当前榜单，确认采用已经审核生效的规则版本；刷新/同请求重放不重复加分。
4. 对演示内容执行隐藏、本人撤回或举报中的一项，查看轨迹；需要冲正时新增反向流水，保留原始事实。
5. 对照组织页面确认普通成员不能修改负责人或其他组织资料。

**通过标准：** 发布前不可被普通访客检索；公开投影同源；隐藏/撤回后地图与论坛同步失效；事件可重放对账；榜单分值来自权威贡献流水。自动证据：`qa/community/`、`qa/campus/campus-ledger-live.json`、`qa/campus/campus-ledger-outbox.json`、`qa/campus/campus-ledger-browser.json`。

## 13–17 分钟：活动、志愿、奖励与运营插入点

1. 成员阅读活动条件并报名；达到容量后另一成员进入候补，前者退出时按顺序晋级。
2. 在已开始的志愿任务提交示例证据，由指定且不同于投稿人的核验者核验。检查服务记录、计分事件和来源回执；投稿人不得自批。
3. 打开演示奖励，阅读资格与期限并明确确认领取；检查实际徽章、外观库存、活动资格或合作凭证中的一种。重复操作不重复分配，历史贡献不扣减。
4. 打开运营模板，查看版本化导入预览、活动排期引用和复盘导出。确认用户尚未提供的权重、预算和具体文案仍待后补，不被示例替代。

**通过标准：** 容量不超额；核验关联真实证据与操作者；撤销可追溯并按原规则冲正；奖励状态对应实际权威发放；运营导入不会自动发奖。自动证据：`qa/activities/`、`qa/rewards/live.json`、`qa/rewards/browser.json`、`qa/operations/`。提醒与重试另有实际 pg-boss 队列证据 `qa/campus/jobs-live.json`，不靠本卡人为等待长时间。

## 17–20 分钟：合作、地点反馈与收尾

1. 从合作流程助手进入获准服务，检查当前来源、维护职责与期限；先选择转交对象和字段，再明确确认申请。
2. 看实际任务状态与回执。外部超时保持待确认，对账后再决定下一步；未连接渠道不能显示商家预约成功。
3. 使用演示权益，由指定核销员核销一次；越权、重复、到期或跨商家核销应拒绝。合作人员仅能查看自家聚合统计。
4. 在地图地点提交非破坏性反馈，由当前获派负责人认领、处理、说明结果；普通访客不能替换场景或更改管理角色。
5. 记录未通过项、测试版本、实际起止时间与证据链接。确认已有备份可在独立命名空间恢复；不得为了完成操作卡覆写原库。

**通过标准：** 信息转交先明确确认，字段最小；未知外部状态不虚报成功；核销只生效一次；反馈权限与处理轨迹完整；七库、附件、队列和知识库恢复以独立核对记录为准。自动证据：`qa/campus/partners-live.json`、`qa/campus/partners-adapter.json`、`qa/partners/`、`qa/campus/environment-live.json`、`qa/campus/environment-browser.json`、`qa/campus/backup-comparison.json`。
