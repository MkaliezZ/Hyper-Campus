# M1 四项优先能力：自动验证记录

状态：**M1_PRIORITY_SCOPE_PASSED**。本次交付不是完整 M1 阶段完成，也不是公网生产认证。

环境：同一 Windows 主机上的 WSL Ubuntu 26.04.1、Node 24.22.1、PostgreSQL 18.6、Keycloak 26.8.1、Nakama 3.41.0、NodeBB 4.16.3。独立 QA Chrome 155 从 Windows 访问 Ubuntu 的回环服务。所有账号和学校均为虚拟测试资料，未读取用户浏览器、用户私有数据库或图纸。

| 验证           | 结果与证据                                                                                                                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 真实服务链路   | integration.json：8/8 通过。稳定三系统映射、两校/组织/合作方隔离、组织邀请不授予学校成员资格、负责人交接与最后 owner 保护、人物与 PG A2A 回执、论坛入队/发布/撤回中断、账本/通知去重、投影修复、学校与 IdP 撤权。最后一轮约 9.8 秒。      |
| 浏览器账号链路 | browser.json：3/3 通过，页面异常为 0。真实 PKCE 注册 → 验证邮箱 → 设置密码 → 指定邮箱邀请入校；另一独立浏览器上下文通过找回邮件修改密码，Base ID 保持不变，旧密码被拒绝。邮件由本机测试 SMTP 接收，不代表实际邮箱送达。                   |
| 邀请权限回归   | permission-regression.json：已有 owner 不会因接受普通成员邀请被降级；旧 JWT 中的邮箱不能绕过当前 IdP 邮箱检查。                                                                                                                           |
| 访客绑定       | guest-binding.json：原签名 Cookie + 一次性声明 + 已验证账号；伪造 Cookie、重复声明、另一账号读取均拒绝，原 A2A taskId 与重复请求回执保留。输入是明确标记的虚拟旧访客。                                                                    |
| 迁移失败与恢复 | migration.json：真实 PostgreSQL 中制造不兼容旧表，迁移失败后旧表和旧数据保留；随后显式备份 JSON 并导入新库，原文件 SHA 不变，回执/ID 保持，重新打开和单写者锁通过。                                                                       |
| 整套恢复       | backup-source.json 与 backup-restored.json：六库 **185 张表、4414 行**逐表核对通过。仅 hd_users.issuer 为克隆新端口做显式归一化；userId 与 subject 不变。备份清单校验 39 个文件（含六份 dump），未覆盖源库。                              |
| 恢复后实际功能 | restore-live.json：原 Keycloak 账号能登录，既有 Base ID、学校隔离、人物存档、A2A 任务和重复回执、Nakama/NodeBB 映射、源事件和贡献账本通过。恢复实例有独立端口、数据库和可写目录。                                                         |
| 实际进程终止   | process-restart.json：在独立恢复的测试实例中，先阻止对账，完成原生发布并确认尚无账本事件；核对命令归属后终止该论坛进程，监督器停止自己的服务。重启后从同一个原生 pid 补出一个事件和一笔贡献，没有再次投稿。原 M0 和当前 M1 实例未被终止。 |
| 原 Base 回归   | base-regression.txt：13/13 通过，包含官方 A2A SDK、跨进程重复请求、取消/中断、知识库隔离与撤回、接待上下文、模型权限边界、共享几何和素材权限。doctor、build、全部公开房间的路径验证通过，见 spatial-verification.json。                   |
| 旧包保全       | protected-deliveries.json：封存 Base v0.2.1、M0 v0.1.0、私有 Plan14 项目附件 SHA-256 均与原记录一致。原 Base 和 M0 源码工作树没有本轮修改。                                                                                               |

过程中发现并修正：JSONB 字段排序导致事件重放误判；IdP 邮箱变化后旧 JWT 的邮箱过期；邀请接受不能覆盖既有权限；组织邀请只能授予组织资格；恢复时本地 NodeBB 插件被复制为普通目录后须同步到实际安装位置；Keycloak 26.8.1 注册页无密码字段时仍绑定密码验证器的上游主题问题。主题修补来源与 Apache 许可见 integrations/keycloak/。

## 明确未验收和后续工作

- 真实 SMTP 的外部送达、学校管理员实际入驻与内容核查未做。
- 公网 TLS、域名、反向代理、非 root 常驻服务、告警、容量和真实 Ubuntu 服务器部署未验收。
- 本次整套恢复是已配置的六库实例；额外远程 pgvector 服务须按其扩展安装条件另行恢复验证，工具在连接缺失时拒绝不完整备份。
- 完整 M1 的私信、实时聊天逐包权限、原生论坛编辑与自动保留/清除策略仍待后续；当前相关原生入口保持关闭。
- M2 正式人物资产/背包、M3–M5 运营/奖励/合作方业务没有提前展开；贡献仍为虚拟规则，等待用户的旧运营材料。
- 一次综合验收按用户的 20 分钟上限收口，本轮没有新增整小时或长时 soak 套件。这里列出的脚本、故障定位和恢复开发总耗时不是单场真人验收时长。
